# Devon Labs project tracking

Read `README.md` and applicable shared project guidance before changing this repository.

- Maintain the central project inventory in `docs/project-inventory.md` when projects are created, materially changed, released, paused, or archived. Verify repository identity, status, and links; consolidate renamed projects, forks, and worktrees instead of creating duplicate entries.
- Record purpose, repository and relevant links, status, last meaningful update, and next steps. Track inventory coverage honestly and expand it incrementally as projects are reviewed.
- The inventory and the curated public portfolio serve different purposes. Update `data/developer-projects.ts` and `data/portfolio-summaries.ts` only when the public presentation should change. Neither a tracking entry nor an agent note authorizes disclosure or deployment.
- Keep all tracked inventory content suitable for this repository's visibility. Do not commit confidential project details; record only public-safe metadata here and retain private details in an appropriate private location.
- For inventory-only documentation changes, review Markdown links, content, and the diff; the app build is unnecessary. Preserve unrelated files and generated output.
